# 先读结论，再查证据

日常从“问题分析”进入报告，先判断发生了什么、为什么、现在怎么做。报告是受授权证据约束的分析结果，仍需核对；真实模型完成不等于语义已确认。当前实际验证结果见[结论优先验收](acceptance-conclusion-first.md)。

## 一份报告怎么读

先核对标题、联合对象、观察窗口、规则 / 真实模型模式及运行状态。失败、待完成、过时或覆盖不足时，应先理解这些限制。

| 摘要内容 | 阅读重点 |
| --- | --- |
| 发生了什么 | 哪个对象出现何种现象，能确认多大影响范围 |
| 独立表层原因 | 数据库、主机等各层的观察与候选机制，是否有反证 |
| 联合根因 | 证据支持的联合候选；资料不足或不适用也应直说 |
| 问题结论 | 现在能确认什么，还有哪些未知 |
| 建议操作 | 先检查或观察什么；人工变更需要哪些条件、批准和复验 |

“已观测”描述有证据的现象，“支持的候选”仍需验证；“证据不足”“不适用”“被反证”都不是失败的分析。人工登记的依赖、曲线同时变化和模型措辞不证明因果，也没有未经校准的根因置信百分比。

建议分为只读检查、观察与人工变更。人工变更必须标明需人工批准、前提与复验；风险标签不构成操作授权。平台和模型不执行任意 SQL、Shell、写库或邮件发送。

## 需要核实时，再展开分析过程

沿引用检查关键事实、支持证据、反证和未知，按需看冻结曲线、关系及文本 / 日志。没有有用资料时应显示缺口，不必为每份报告展示全量曲线或空图。

核对同一对象、同一窗口、单位与统计口径：首末值不是极值，累计量不是窗口增量，恢复后的样本不证明整个历史窗口健康。图表覆盖与模型输入覆盖不同，抽样、截断和预算省略要分别看。

旧报告绑定不可变清单与时间窗。进入“数据查看”会查询当前选择窗口，不补写旧报告；新的分析另存版本。旧报告缺少完整结论摘要时显示旧版提示，保留其原内容，不以规则拼接伪装成当时的模型输出。旧 ID 链接只进入有权限的只读历史或明确退役页。

## 四入口与配置

- **问题分析**：读问题、风险、巡检状态和报告。
- **Zabbix 接入**：连接只读来源，按 host / item / tags 组成联合分析对象。
- **数据查看**：查数值、类型化历史、新鲜度和缺口。
- **配置**：维护巡检、模型与外发、必要账号授权及审计。

新部署 `collection_mode=zabbix_only`，只使用已有 Zabbix 监控。旧直连、自定义采集模板及单 host 独立对象入口已退役；`legacy` 只保留历史兼容 / 旧测试，不用于绕过当前产品边界。历史读取、暂停及归档仍按当前权限。

`rules_only` 不调用模型，不伪造执行摘要。`live_redacted` 需要私密供应商设置、当前业务授权与明确外发许可。DeepSeek 等模型为可选配置，公开仓库不硬编码个人 Pro 账号。新请求最多 24,000 字节输入、3,000 tokens 输出，仍服从更低显式预算和调用、累计 token、费用及工具限制；预算增加不保证完整覆盖任意范围。

敏感原文读取权和模型外发许可分开。名称、单位等元数据也要受限投影；自由说明保留本地。无原文权限不能解释成没有数据，来源管理权限也不等于业务证据读取权。

## 已知限制与实际结果

上一轮联合对象锁报告虽有正确锁链引用，仍误读 CPU 区间；更早报告曾因预算省略整组曲线。这些历史结果和失败保留在[联合对象验收](acceptance-analysis-groups.md)与[旧版验收](acceptance-zabbix.md)，不因新报告结构或预算更新而改写。

本轮真实模型字段投影、数字和建议语义应逐项复核，不能只凭结构校验或 completed 宣称通过。[本轮验收](acceptance-conclusion-first.md)记录实际结果和剩余限制。项目属于个人隔离 Lab，不主张生产采用、自动修复或通用准确率。
