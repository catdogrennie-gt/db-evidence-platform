# 公开演示：开启问题，观察证据，再看结论

这个入口用于演示一次完整的 Zabbix → 联合分析 → AI 报告流程。实验在专用 MySQL Lab 的合成订单表中运行，真实制造事务锁等待；监控值和快照来自实际采样。它不代表生产事故、生产采用或自动修复能力。

## 怎么看

使用 README 的专用 `demo` 账号进入“演示”。固定目标已配好，不用提供数据库密码，也不用选择 SQL、主机或模型。

1. **先看报告。** 页面保留已产生的冻结报告，顶部给出现象、原因判断、结论和建议操作。标为历史的报告只属于它标注的时间窗。
2. **开启开关。** 服务端核对隔离目标、记录本轮任务，再制造固定的单行事务等待。所有访客共用同一轮，不会各自注入。
3. **等实际证据。** 平台主动从 Zabbix 读取数据。取得本轮新鲜、完整的非空锁快照后，才把固定问题交给模型；没有证据就不生成“成功诊断”。
4. **查看本轮报告。** 分析完成后先读摘要，需要核实时再看冻结曲线、引用和分析过程。模型分析失败、额度不足、缺数及未知原因都会明确显示。
5. **关闭开关。** 回滚本轮事务，检查专用连接已关闭、锁等待已清除、实验数据未变，再等 Zabbix 的新鲜空锁快照。直接清理和监控复验是两个独立状态；缺少后者不显示整轮复验成功。

开关关闭不会改写已冻结的故障报告；报告描述当时的观察，恢复记录描述之后的新观察。等待恢复样本时禁止开启下一轮。

## 为什么会等待

进度显示已记录的里程碑和时间，不使用模拟百分比。采样由 Zabbix 的实际周期决定；本演示锁快照为 30 秒，模型耗时也会变化。刚开启就关闭可能来不及采到故障，这时可以验证清理，但不能得到一份新的故障分析。

历史查询只取最近几条而产生的 `history_truncated`，与当前 JSON 快照是否完整分开处理。演示要求生产者契约 `db-evidence-lock-snapshot-v2`、明确完整性和行数，以及固定来源、host/item、映射版本、配置版本和本轮时间都匹配。不能用旧快照或空历史代替故障 / 恢复证明。

UTC 日界为北京时间次日 08:00。停止不受冷却或额度限制。浏览器关闭、刷新和网络断开不会延长故障时限。会话过期需要重新登录；页面连接异常会把保留快照标为过期，倒计时结束本身不是恢复证明。

工作进程丢失后只允许清理与复验，不重放注入。无法确认目标身份、连接关闭、锁状态或数据一致性时，维持禁止新实验，等待运维人员处理来源或运行环境。

## 账号能做什么

公开账号只有固定 Lab 联合对象的数据读取和这一种实验的开启 / 停止能力。没有通用分析创建、任意模型调用、配置修改、敏感文本读取、采集触发或 SQL / Shell 执行权限。

真实分析由另一个限制在同一对象的服务身份提交，保持既有模型外发许可、脱敏、输入预算和工具权限。网页不接收数据库连接参数、故障 SQL、命令、提示词、模型或时长。

公开密码只属于 README 指明的这个演示部署；新安装没有默认账号或通用密码。示例和私密部署文件不应混用。临时公网地址依赖演示电脑开机联网，重建隧道可能换地址；它不承诺持续在线。

## 自行部署

在已有可运行的 Zabbix 联合对象基础上，部署者另外准备专用 Lab、低权限 `demo_scenario` 身份、SSH 已核对主机密钥、UUID / Lab 标记、数据摘要和仓库外目标配置。参考传输实现 `platform_app/demo_fault.py`；它不是通用故障注入框架，不应指向业务数据库。

先停止本部署 API / worker，执行迁移到 `0007_demo`，再显式配置：

```powershell
.\.venv\Scripts\python.exe scripts/platform/prepare_demo.py `
  --config C:\Private\config.json `
  --instance-id REGISTERED_LAB_GROUP_UUID `
  --source-id REGISTERED_ZABBIX_SOURCE_UUID `
  --lock-itemid LOCK_SNAPSHOT_ITEM_ID `
  --lock-hostid MYSQL_HOST_ID `
  --password-file C:\Private\demo-password.txt `
  --target-config C:\Private\target.private.json `
  --accept-isolated-lab
```

上面的路径和标识是说明占位值，不是可用凭据。工具只维护两个专用平台身份的精确对象授权，拒绝覆盖同名的其他用户 / 角色；私密配置和密码文件必须在源码仓库之外。配置写入和控制库事务不能跨资源原子提交，失败后保持服务停止并重新执行核对，成功后再启动服务。

部署后仍需真实验收，不能把单元测试代替 MySQL 跨进程互斥、故障实际生效、Zabbix 取证、模型调用和恢复复验。查看[本轮验收](acceptance-public-demo.md)。
