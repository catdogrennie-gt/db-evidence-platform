# 技术架构与开发过程

## 一句话介绍

DB Evidence Platform 是一个基于已有监控数据的数据库问题分析平台：复用 Zabbix 采集，把同一业务的数据库、主机监控及已采集日志放在一起，定时检查问题，结合 AI 给出解释、建议和依据。

它将“收到告警后人工翻曲线、核对状态和日志”的一部分工作整理成持续运行的分析流程，当前以 MySQL 场景为主。采集和规则负责确定事实，AI 辅助解释和关联，数据库变更由人员控制。

## 1. 系统由什么组成

| 模块 | 实现 | 作用 |
| --- | --- | --- |
| 前端 | React / TypeScript / Ant Design / ECharts | 展示问题结论、指标曲线、分析依据和配置页面 |
| API | Python / FastAPI / SQLAlchemy | 登录、授权、接入管理与查询 |
| 采集 worker | Python 后台进程 | 按计划取数、检查异常并调度调查，记录采样时间与缺口 |
| AI worker | Python 后台进程与受限工具调用 | 消费分析队列、组织分析证据并调用模型生成报告 |
| 控制库 | MySQL / Alembic | 保存组织与权限、联合对象、任务、采样、事件、报告和分析证据 |
| 模型 | DeepSeek API，可选规则模式 | 解释现象、关联线索、提出下一步建议 |

采集和 AI 使用独立队列，任务状态保存在控制库。AI 请求较慢或失败时，采集继续运行，失败记录保留。当前主流程不要求 Grafana 或 Prometheus；图表由前端 ECharts 展示。

## 2. 数据从哪里来，怎样接入

平台通过 Zabbix JSON-RPC API，以独立只读身份获取主机、监控项、标签和历史记录。主路径不需要业务数据库连接口令。

用户先选择允许使用的主机组，再按 host / item / tags 查找具体监控项，把同一 Zabbix 来源、同一所属业务系统的数据库与服务器数据组成一个联合分析对象。目前每个对象可选择 1–32 个确切监控项，支持数值、文本和日志类型。

例如，把一个订单数据库的连接数、锁等待、SQL 摘要和所在主机的 CPU / 内存放在一起分析。MySQL、Linux 官方模板负责基础采集；项目另提供 Zabbix 诊断扩展补充锁快照和 SQL 摘要。日志和诊断信息必须先被 Zabbix 采集，平台不能从不存在的数据推导结论。

操作见[联合对象指南](analysis-groups-guide.md)，采集配置见[官方模板与扩展](zabbix-official-setup.md)。

## 3. 自动化与 AI 分别做什么

自动化流程包括定时取数、信号检查、异常去重、调查排队和报告保存。后台既可按周期综合检查，也可在发现新异常后安排分析，受权限与调用预算控制。

AI 使用当次分析窗口内保存的证据，通过只读工具查看获准的指标、锁关系、SQL 摘要及其他受限诊断摘要；普通 Zabbix 文本和日志原文不直接发送给外部模型。它没有业务数据库直连权限，也不能执行自由 SQL 或 Shell。

报告先展示现象、表层原因、联合候选原因、结论和建议，再按需要提供图表、关系和引用。证据不足时说明尚不能确定什么、还需要检查什么。关联变化是分析线索，不会自动被当作已证明的根因；缺少数据也不会被当作零值或健康。

外部模型为可选能力：`rules_only` 不调用模型；`live_redacted` 需要配置模型供应商、相关对象权限和明确的数据外发许可。当前已用 DeepSeek API 做过实际分析，失败与历史结果也保留在[实验验收](acceptance-quick-showcase.md)中。

## 4. 怎样控制数据访问和风险

- **上游只读**：Zabbix 凭据限定到授权主机组，平台不以采集身份修改业务数据库。
- **范围授权**：角色控制可做的动作，部门、系统与对象范围控制可看的数据。后端每次查询和 AI 工具调用都会检查权限；管理员角色不自动拥有业务证据。
- **敏感数据单独控制**：日志、文本原文需要额外权限；数据查看权与模型外发权分别授予，外发使用受限脱敏证据。
- **凭据与登录**：Zabbix 凭据在服务端加密保存，主密钥和私密配置在仓库外；采用服务端会话、注销撤销、CSRF 与同源校验。
- **执行边界**：AI 只给建议，重要操作由人判断、实施并验证；独立演示工具只能操作预先登记的隔离测试目标。

## 5. 是个人项目还是团队项目，用了哪些工具

这是个人主导的作品：本人负责需求、数据库运维场景、架构选择与验收；Codex 辅助方案拆解、前后端代码、调试、测试和文档。开发中参考 Superpowers 与 OpenAI Skills 的设计、排障和验证方法，具体记录见[技能与参考资料](platform/05-skills-and-references.md)。

使用 pytest、前端测试与浏览器验收检查功能；用 VMware / Docker 中的隔离 MySQL 制造受控问题，验证采样、发现、报告、权限与恢复；Git / GitHub 用于版本管理和公开展示。

Codex 是开发助手，DeepSeek 是项目运行时的可选模型，两者职责不同。项目由个人推进，采用 AI 辅助开发，当前验证环境为个人隔离 Lab。

## 7. 如何部署与查看实现

从[部署指南](platform/07-operations.md)准备独立控制库、私密配置、账号、迁移和服务，再按[使用指南](user-guide.md)接入 Zabbix。完整平台不依赖独立快速演示站，演示工具只是额外的验证入口。
