# 相邻观测边界保留实施计划

**Goal:** 在现有请求预算内保留已有冻结快照的首末非空及相邻空样本。

**Architecture:** 在model_context增加纯引用选择器，供初始请求与最终压缩的受保护集合复用；不改采集、授权或原报告。

**Spec:** [设计](../specs/2026-11-13-snapshot-boundary-retention-design.md)。依照既定持续演进授权直接执行，不重复征求日常工程选择。

## 约束与审查重点

- 原48000输入、96000累计部署预算不变；全套默认24000/32000亦须回归。
- 跨实例/来源/模板/主机/监控项隔离；未知身份、同刻冲突、无效时刻及不可用样本不得证明先后。
- 全空正常反例不产生异常锚点；原对象和证据不变。
- 最小预算下保护内容无法装入则失败关闭，不删关键引用骗过验收。
- 已有初始包之外的样本不声称保留；离线捕获不冒充实际新模型调用。

## 顺序

- [x] 真实冻结数据只读核对及封存16离线生产路径重放：初始包含关键样本，实际请求丢失，且重放输入与原调用一致。
- [ ] 新增独立边界/隔离/正常/预算及生产请求路径回归，观察失败。
- [ ] 仅修改选择器及两个受保护集合，重跑相关回归和真实离线捕获。
- [ ] 独立代码审查、修复重要问题，干净候选检查；未满足则不部署。
- [ ] 更新状态、场景卡、手册与私密CHECKPOINT。已通过改动按既有公开源码/封存/通知/交接流程继续，来不及部署明确WAIT。
