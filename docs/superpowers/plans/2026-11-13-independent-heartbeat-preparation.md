# 独立心跳正常基线准备

> **For agentic workers:** 使用 superpowers:executing-plans 在当前会话逐项执行，完成后独立审查。

**Goal:** 为 DATA-QUALITY01 的真实停更验证取得独立、可停止、不会影响数据库的心跳来源与正常反例。

**Architecture:** 复用登记 Lab 主机与 Zabbix history.push，新增两个明确标注的实验 trapper 项。发送恒定值1但更新时间；一个每5秒保留，另一个按30秒心跳保存，确认值不变和稀疏合法保存不等于来源停更。平台经既有只读来源和自然采集读取，不手工创建分析报告。

**Tech Stack:** Zabbix 7 API、既有分析对象接口、独立私密有界工程脚本。

**Spec:** [持续演进规范](../specs/2026-11-13-continuous-evolution-design.md)与[数据质量场景](../../validation/data-quality-01.md)。

## 约束与审查重点

- 仅新增固定两个实验监控项、一个无模型策略的测试对象；不得改既有主机/数据库监控项。
- 写前保存意图；创建结果不确定时读回，禁止盲目重放创建或另起身份。
- 发送总时长不超过210秒、每5秒最多两条；保持独立控制库与公网服务不变。
- 不把API接受等同于Zabbix已保存，不把配置周期等同于真实样本，不把人工采集等同于自然采集。
- 退出先暂停自己的对象，再停用自己的新增项，保留身份及历史；无故障ON、无模型调用。
- 本轮不进行停更故障；独立恢复护栏及故障GO仍需后续准备。

## 执行

- [x] 只读核实登记主机、现有API能力、允许发送来源与官方保存语义。
- [x] 创建固定实验项，发送正常心跳并核实实际历史：主项19条、5—6秒；稀疏对照4条、31/30/31秒。
- [x] 选择到一个测试对象，自然入库：3次成功采集、6份证据，当前覆盖缺项0；无模型策略。
- [x] 暂停新增对象/监控项：对象版本2、两个新项停用，原项未改。手册与连续卡已更新；公网收尾检查结果另记进度。

## 完成标准

完成本轮仅表示正常数据准备成立；不表示停更发现、模型解释或新公开场景已经通过。发生失败保留原始证据，定位最早失败层，后续继续同一身份。

## 第二步：独立期限与退出预演（22:16续做）

保持原两个监控项和原对象，不创建策略或新身份。私密固定发送进程持有排他运行锁，启用前重检对象版本及项身份；内部单调时钟限制总寿命与单次主发送暂停，不能靠改文件续期。只接受同一随机所有者的固定动作，不接收SQL、Shell、目标地址或任意项编号。

- [x] 先以失败回归验证暂停到期自动恢复、重复命令不续期、无效请求默认发送、总期限不可延长：5项先失败后通过。
- [x] 私密发送进程使用同一契约；到期暂停原对象到版本4、停用原两个项，并独立读回，不停止公共服务。
- [x] 短命驱动自行退出；此后22条主项/4条对照真实样本、6次新自然采集。发送器120秒后独立收尾并保留历史。
- [x] 独立审查及现场读回通过。本次现场拒绝暂停命令，不记作停更发现或AI分析通过，实际停更GO仍WAIT。

预演总发送期限120秒，禁止建立公开接口。硬终止发送器自身、断网及电脑关机均不在此次驱动退出预演的证明范围；这些情况仍需实际读回和人工核查，不承诺通用自动恢复。
