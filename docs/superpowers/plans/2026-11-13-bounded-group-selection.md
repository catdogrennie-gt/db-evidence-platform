# 联合对象有界选择调整

遵循[持续演进规范](../specs/2026-11-13-continuous-evolution-design.md)，接续[TXN-HISTORY01](../../validation/txn-history-01.md)。实际对象32项已满，再选择上游写入活动与重启上下文会被接口拒绝；保留已有诊断项，避免为了一个案例移除其他案例的证据。

设计：前后端选择上限由32改为40，关系上限仍32；来源客户端48次/30秒预算、单项历史行数、权限、冻结、模型输入及费用预算不变。一次采集最多40次历史读取加3次目录/依赖主项元数据读取，仍在48次预算内。不是完整采集或完整模型上下文的保证，超时和缺项继续明确保留。

1. 先以当前代码验证34/40项保存失败，增加41项拒绝、配置修订和身份保留、40个依赖项自然处理不丢项/不越调用预算的回归；同步前端跨页选择和提交边界。
2. 实现统一上限常量，前后端边界一致；运行相关回归、完整后端/前端及构建。用现有授权源做只读有界查询测量；不能用替身耗时宣称真实性能。
3. 独立审查后封存候选。部署、真实选择调整和自然采入分别记录；旧公共服务保持原版本，未部署前不写功能已上线。之后再验证原周期AI路径，真实失败才决定规则改动。

本调整不新建资产、身份、模型策略或故障，不提高模型额度，不手动触发报告。正常反例与因果边界仍沿用场景卡。
