# 控制MySQL的缺失恢复判定

延续STARTUP-01及其依赖审计，当前控制库实际可用，主机侧恢复入口未齐。本轮只实现可独立验收的启动许可判定与本机只读适配；不停止当前数据库、不初始化目录、不登记自启动。平台AI不接入这些工程工具。

采用独立纯函数判定：私密契约固定程序/配置指纹、目录及原UUID、回环地址和端口；新鲜观测说明文件、所有MySQL进程、监听和实际只读探测。正确运行则无动作，存在但未就绪则等待，配置/目录变更或身份/端口冲突则拒绝；只有原目录完整、没有对应进程/监听及未知MySQL范围时，才返回待执行的启动需求。结果不包含私密路径、命令、UUID或配置内容。

相比直接重复运行旧脚本，这样不会混用历史部署或初始化已有目录；相比本轮重写完整服务管理，只处理一个共享数据依赖，便于保留对外服务。`start_required`是判定结果，不是执行成功。实际启动、跨执行者互斥、启动后就绪等待、开机任务与整机重启验证均为后续工作。

输入无效、过期、文件指纹不符、未知进程范围、同目录多进程、占端口、错误UUID均拒绝。文件系统与进程信息由可信本机适配器获取，纯函数不具备文件读取、网络、SQL、Shell或进程执行能力。离线测试覆盖合法缺失、正常存在、启动中、冲突及正常其他目录实例；实际验收只观察当前正常控制库，无启动动作。
