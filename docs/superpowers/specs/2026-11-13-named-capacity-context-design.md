# 容量事实的模型输入表达

本项承接已授权的持续演进闭环，修复 CAPACITY-06 暴露的解释输入可读性问题，不增加模型权限或预置场景答案。实际请求已经带有 80% 关注水位，却与其他类型计算合成几十列、许多空值的位置数组；报告未明确配置水位，且将低运行线程数用于推断处理未饱和。

选择：保留 `capacity_pressure` 的原有具名计算对象，其他数值和基线计算继续按已有方式压缩。相较继续加提示词，这样不增加解释指令；相较重新设计整套输入协议，改动只在投影表示，不改变规则、事实或授权。所有用量、上限、水位、状态、时间配对、单位和操作数引用保持原值；不注入“应答”、故障标签或根因。

正常与恢复状态也保留原样，不能统一写成风险。最终预算不足仍按现有规则失败，不静默删除必要引用。历史冻结证据和旧报告不修改；输入版本升级到 v4.7。程序回归只证明传递契约，是否改善真实诊断须另做一次有界自然验证。公开 API、采集器和演示维护状态保持可用。
