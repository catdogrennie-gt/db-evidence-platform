# Zabbix 联合巡检操作指南

日常从“问题分析”开始，先读发生了什么、为什么和怎么做，再按需核对证据。当前结果以[结论优先验收](acceptance-conclusion-first.md)为准；结构和引用校验不替代真实模型语义复核。上一轮[联合对象验收](acceptance-analysis-groups.md)和[旧版验收](acceptance-zabbix.md)保留原输出、失败与限制。

## 从哪里开始

| 入口 | 用来做什么 |
| --- | --- |
| 问题分析 `/` | 查看问题、风险、最近巡检状态与覆盖缺口，打开报告 |
| Zabbix 接入 `/monitoring` | 连接只读来源，选择 host / items / tags，维护联合对象 |
| 数据查看 `/metrics` | 查询当前窗口的数值、类型化历史、来源与缺口 |
| 配置 | 设置巡检、模型与外发、必要账号授权和审计 |

后端按当前业务权限控制列表、数量与读取。来源管理员不会自动获得业务证据权限；空列表不代表健康。旧直连、自定义采集模板、单 host 独立对象创建及旧平台导航已退役；含历史 ID 的链接只能进入授权只读历史或退役提示，不用当前数据替代旧记录。

## 首次接入

### 1. 连接已有 Zabbix

在“Zabbix 接入”登记名称、API 地址、所属业务系统、只读 Token 与允许主机组。保存并验证连接，核对可见主机和最近成功时间。凭据加密保存在服务端，不返回旧 Token，不写入文档或截图。已有对象绑定后不把来源地址改指另一套 Zabbix，需要不同来源时另建。

平台复用已有监控，不会因保存对象自动安装 Agent、建数据库账号或改模板。模板名和来源连通都不证明锁、SQL、日志已有数据。准备资料见[官方模板与诊断扩展](zabbix-official-setup.md)。

### 2. 保存联合对象

在“Zabbix 接入”点击“新建联合分析对象”：

1. 选择一个来源，填写名称、分析目标和采集周期，继承来源业务系统。
2. 按 host、名称 / key、主机或 item 标签筛选，勾选 1–32 个具体 items；核对单位、值类型、状态和最近实际采样。过滤与翻页保留选择。
3. 可选登记已选 host 之间的关系，最多 32 条。关系是人工登记，不是因果事实。
4. 检查组成与缺口，保存后进入“查看数据”或“配置巡检”。

范围限定同一来源、同一业务系统，只包含精确选中的 items，不自动纳入 host 的其他监控。未知 key 可选，已知 key 仅用于语义增强；hostid 不当作 MySQL UUID。此路径不需要目标数据库口令。更多例子见[联合对象指南](analysis-groups-guide.md)。

### 3. 检查数据与覆盖

数值按原时间和单位绘图，字符 / 文本及日志以有限历史单列，二进制不伪装成数值。缺失不补零；来源离线、读取失败、unsupported、过时和预算省略均需分别解释。

文本 / 日志原文需要该组范围的 `evidence.read_sensitive`。没有权限不等于没有数据；能读取原文也不等于可以外发。自由说明保留本地，任意 key 参数与不安全元数据不直接送入模型，专用诊断信息经过受限字段投影。

官方模板可能按值变化 / 心跳稀疏保存 history。采集周期、保留间隔、最近实际记录是不同概念。短窗无新记录需核对实际采样、心跳及覆盖原因，不补旧值为当前测量，也不直接判定故障。对象最近有观察不代表每个 item 都新鲜。

### 4. 配置后台巡检

在“配置”的巡检设置中指定负责人、授权对象、模式、周期、冷却和每日预算，再启用。数据采集默认 60 秒，可设 30–3600 秒；轻量规则检查默认 300 秒，综合巡检默认 1800 秒。异常紧急通道仍受冷却、队列、预算与授权约束。

`rules_only` 产生确定性规则和覆盖结果，不调用模型、不伪造实时 AI 摘要。`live_redacted` 另需私密供应商设置、当前业务授权和明确外发许可。DeepSeek 等为可选供应商，公开配置不绑定个人 Pro 账号。新模型请求最多 24,000 字节输入，输出可配置到 3,000 tokens，仍尊重更低显式预算；裁剪、省略、累计 token、调用次数、费用及工具限制继续有效。

单次调查最多五个资源，每位用户最多三个在途调查，较大范围分组调度。组内 host 数不是数据库实例数。后台不依赖浏览器常开；正常周期保留历史。负责人撤权、策略停用、外发未许可、来源离线或预算耗尽时查看停止原因，不扩大权限继续分析。

## 日常阅读报告

先核对模式、对象、窗口与运行状态，再读五项摘要：**现象、独立表层原因、联合根因、问题结论、建议操作**。候选解释、证据不足、不适用与被反证均有各自含义，不等于已证明业务根因。

需要核实时展开“分析过程”，沿引用看关键事实、支持与反证、未知、冻结曲线、关系及文本。详细步骤见[结论优先阅读指南](conclusion-first-guide.md)。登记关系与同时变化不证明因果；首末值不等于极值，累计量不等于窗口增量，恢复后样本不证明整个历史窗口健康。

报告使用不可变证据清单、对象组成和窗口。模型输入覆盖与图表保留范围分别查看；抽样、截断或省略不表示完整原始历史。进入“数据查看”会查新窗口，不补写旧报告。旧版缺少完整摘要时保留原文和旧版提示，不用规则补成历史 AI 输出。

建议可能是只读检查、观察或人工变更。人工变更需明确批准、前提与复验；风险标签不是授权。人员在外部执行实际操作，使用后续有效样本复验，平台与 AI 不执行 SQL、Shell、写库或邮件发送。`improved`、`not_improved`、`inconclusive` 按实际证据解释，模型写“恢复”不能替代复验。

## 修改、暂停与历史

编辑范围应基于当前配置版本；冲突时重新读取，避免覆盖他人修改。来源与系统归属不重指。变更推进版本，旧在途结果不能覆盖新范围；已有报告保留原冻结内容。暂停停止新采集与相关巡检，重新启用后核对新样本和策略状态。

新部署默认 `collection_mode=zabbix_only`。旧直连、旧单 host 采集不再调度，切换前入队任务也受执行边界限制；`legacy` 仅作历史兼容与旧测试。历史读取、暂停与归档仍按当前权限，不级联删除证据。

## 遇到这些状态时

| 现象 | 下一步 |
| --- | --- |
| 来源连通但数据为空 | 核对允许主机组、精确选择、窗口及 history 保留，不用演示数据填空 |
| 有指标但没有锁 / SQL / 日志 | 按真实能力与缺口继续调查，不从模板名推断存在 |
| 数量与维护者看到的不同 | 核对业务范围；来源管理权限不同于资料读取权 |
| 来源过期或失败 | 核对最近有效观察及原因，旧值不代表当前健康，失败不直接证明目标宕机 |
| 模型失败或未运行 | 查模式、权限、外发、预算与队列；保留失败，继续看规则和证据 |
| 旧报告与当前数据不同 | 核对各自窗口与版本，历史冻结不会跟随新查询变化 |
| 原文无法读取 | 核对组范围敏感读取权限，不解释成未采集 |
| 旧 ID 链接不能进入当前页面 | 使用授权只读历史或查看退役说明，不重建历史为当前观测 |
