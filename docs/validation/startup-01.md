## 一条检查流程

封存版本与登记角色 → 新鲜Windows进程及监听快照 → 对照路径/命令哈希/创建时间/PID/父PID → 同类消费者控制库范围 → 端口与依赖 → 只含逻辑名称和原因码的结果。

初始25项程序检查通过后，独立审查发现只比较命令指纹会漏掉不同启动参数的同库消费者；4项回归先失败，增加角色+规范化控制库目标哈希及未知范围阻塞。私密Windows适配器首测又把venv启动器当成消费者，改为仅折叠已知venv路径、父子关系及同参数向量的重定向启动器。

后续审查补齐带引号/连写模块参数、pythonw、不可读取身份、重复配置参数及相对配置路径等边界。相对/UNC路径不猜测工作目录，不读取并返回未知范围。所有失败记录保留，不删除不明进程来让检查通过。

## 仍未实现或未验证

完整依赖恢复、自启动登记、重启后控制器状态与清理、临时隧道变址后配置/链接更新仍WAIT。旧桌面入口未替换，本轮不能拿它恢复当前演进版。没有新数据库故障、实际模型分析或新增A场景。

下一步只推进统一恢复的一个环节：先核对本地数据服务与VM依赖的既有启动所有权和只读就绪，再设计“缺失才启动、身份不明拒绝、健康组件保持运行”的有界恢复顺序；不直接运行历史脚本，不以电脑重启当验证手段。实际进展见[演进状态](../evolution-status.md)。

## 19:24续查：当前依赖可用，主机恢复登记仍缺

同一STARTUP-01续做，18:49起累计工程时间约32分钟，未另开场景或重置计时。本阶段仅执行固定只读查询、服务/任务枚举、VM清单及SSH诊断；不启停组件，不改巡检、故障、凭据、启动项或模型预算。

原始审计先假设唯一来源而拒绝，改为明确登记来源；初版将历史未启用映射一起统计，112项中有1禁用，限定启用且选中对象后为111项全部可用。两个口径保留，不把历史禁用项当当前采集故障。配置默认Prometheus端点不可达的事实也保留，不因另一个进程可用便宣称绑定正确。

独立审查发现初始文件系统命令把两项查询串联，只记录了末项退出码，掩盖前项没有JSON的问题。已拆为根目录挂载、实验目录挂载和空间查询，各记退出码、错误字节数，挂载项还验证结构化结果；真实重测两项JSON均存在、退出0，错误输出0。初始失败证据不覆盖。

本轮交付是依赖缺项证据及审计修正，无新增产品代码或实际故障；原1287项后端及29项检查器结果属于上一轮，本轮未重复全套测试。13组件检查与公网首尾检查另记，HTTP检查不冒充浏览器视觉验收。API/前端17、采集16、AI18未切换，所有运行恢复仍WAIT。

下一步限定到控制MySQL缺失恢复：沿用原数据目录和UUID登记启动契约；先证明正确已运行服务为无动作、冲突/未知身份拒绝、合法缺失仅计划一次启动，再考虑接入实际恢复器。不得初始化数据目录、默认启动全部旧容器、重放已暂停负载或借此增加AI执行权限。

## 20:04续做：纯启动判定通过，Windows集成保守拒绝

同一STARTUP-01连续推进，累计工程约53分钟。本轮交付控制MySQL启动许可的纯判定代码；没有执行器，不具备启动/停止/初始化或自启动能力。平台和A仍保持原版本运行。

契约固定程序/配置文件指纹、数据目录及原UUID、回环地址和端口；可信观测包含文件、所有MySQL进程范围、监听及只读探测。正确运行返回无需动作；已有进程未就绪返回等待；未知范围、重复、端口冲突、文件/目录或实际UUID不符均拒绝；合法缺失只返回待执行需求。状态与原因码不包含私密路径、UUID和原命令。

- 初始无条件请求启动的反例32项失败、3项通过；最小修复后35项通过。审查发现无关低端口监听会误拒绝，新增3项先失败，修正通用观测端口范围；连同CLI隐私检查，最终39项新回归通过。相关检查77通过、11跳过，干净公开候选完整后端1326通过、25跳过、6子检查，92.73秒。前端未改变、未重跑。
- 私密Windows观测器严格识别登记程序与单一`--defaults-file`参数，不支持的覆盖参数、配置组、继承默认项和选项均视为未知；确认端口属于登记程序/配置/目录且文件指纹一致后，才允许发送数据库认证。只读SQL核对UUID/端口/目录，前后进程和监听身份须稳定。适配器18项通过；选项组误读与端口认证边界均保留失败回归。
- 初次实际观测先暴露控制配置为类型对象、不能按字典访问；修正后实际输出为`refused / duplicate_mysql_process`。独立进程核对确认登记的Windows MySQL有同参数父子进程，端口由子进程持有。未直接忽略父进程，未删除进程或放宽重复规则；恢复契约仍未登记，已写的候选代码保持固定且不覆盖。
- 独立审查确认纯工具可按“代码通过、实际集成WAIT”发布，不代表Windows判定适配、缺失启动或冷启动已成功。真实拒绝结果及私密观测保留在仓库外，不伪造无需动作的通过记录。

下一步只核实当前登记父子进程的角色和可接受的归并条件，为真正独立的同目录重复进程保留拒绝回归；在实际正常实例得到可信无动作结果前，不添加执行器或自启动，不重新执行失败登记来碰结果。代码验收与真实集成、服务恢复分开。
