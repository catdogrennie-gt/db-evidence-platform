# 联合分析对象：把已有 Zabbix 监控组成巡检范围

这是当前“Zabbix 接入”页面的主流程。一个联合对象选择**同一 Zabbix 来源、同一业务系统中的 1–32 个具体 items**，可以跨多个 host。它用于共同观察数据库、Linux、应用或连接探针的数据，不把多个 host 冒充多个 MySQL 实例。

日常入口见[操作指南](user-guide.md)，先读结论见[结论优先指南](conclusion-first-guide.md)，部署见[安装与运行](platform/07-operations.md)。当前四入口为问题分析、Zabbix 接入、数据查看和配置。本轮实际结果见[结论优先验收](acceptance-conclusion-first.md)，上一轮限定结果见[联合对象历史验收](acceptance-analysis-groups.md)，两者分别解释。

新部署默认 `collection_mode=zabbix_only`，仅复用已有 Zabbix 监控。旧直连、自定义采集模板和单 host 独立对象入口已退役；`legacy` 只用于历史兼容 / 旧测试。旧 ID 可按当前权限只读历史或查看退役提示，不进入当前数据冒充原记录。

## 先确认监控确实存在

平台读取 Zabbix 已有监控，不会在建组时自动安装 Agent、建立数据库账号或修改模板。

从零准备数据时，先按[官方模板与诊断扩展说明](zabbix-official-setup.md)接通原生 Agent 2，核对实际历史，再进入下面的对象向导。

上一轮在独立 Lab 中使用原样官方 Linux 与 MySQL by Zabbix agent2 模板，通过原生 Agent 2 实际采集。锁链、SQL 摘要等额外诊断放在独立扩展模板，来源和统计语义分别标明。CPU、内存、文件系统、QPS、线程及诊断代表项的连续两轮真实 history 已推进；需要更长基线的计算项仍可能 unsupported，不能把模板存在或 Agent 本地自测当作全部采集成功。

维护者先在“Zabbix 接入”登记只读 Zabbix 来源，明确所属业务系统和允许主机组，再验证连接。来源管理与业务数据读取分开授权，管理员不会自动获得全部业务资料。此路径无需目标数据库口令；密钥只保存在部署环境。

## 四步新建一个对象

在“Zabbix 接入”点击“新建联合分析对象”：

| 步骤 | 怎么操作 | 核对什么 |
| --- | --- | --- |
| 定义范围 | 选来源，填写名称、分析目标和数据采集周期 | 来源决定业务系统；首次保存后不再换来源或系统 |
| 选择数据 | 选择多个 host，按名称 / key 查询，或按主机 / item 标签筛选，勾选 1–32 项 | 主机、itemid、单位、值类型、最近实际采样与状态 |
| 登记关系 | 可选登记两个已选 host 的运行、依赖、连接或关联关系，最多 32 条 | 这是人工登记的关系，不是自动发现或因果结论 |
| 核对保存 | 检查选中项和缺口，保存后“查看数据”或“配置巡检” | 开启数据采集不等于已经启用模型巡检 |

例如建立“订单系统 · 数据库与主机”，同时选择 MySQL 的连接数、查询活动、锁诊断，与 Linux 的 CPU、内存、文件系统和磁盘资料。若来源已有应用耗时或连接探针，再按实际 item 纳入；没有的数据不凭空补齐。建议先选与分析目标有关的小范围，再扩充。

标签支持等于、包含、存在筛选；查询、翻页或更换过滤条件不会清空已选项。标签按列表保留，同名多值不被合并成单一值。官方模板的普通 tags / 元数据即可辅助选择，不强制给未知 key 添加固定语义标签。

一个 host 上的两个同名项、不同 host 上的同名项都按来源内 hostid / itemid 独立保存。只有选中的 items 会成为组的采集范围，不自动包含同一 host 的其他项。未知 key 可以接入，已知 key 只为额外 MySQL 语义增强提供线索。

## 查看数据：按值类型读

点击对象卡片“查看数据”，沿当前页面时间窗查看数值指标，或打开单项历史。

| Zabbix 值类型 | 页面与分析中的处理 |
| --- | --- |
| 数值：浮点 / 无符号整数 | 保留来源、时间和单位，可画曲线并进入受约束的数值分析 |
| 字符 / 文本 | 显示可用性和有限历史，不转换成数值折线 |
| 日志 | 以有限原文及实际日志元数据单列，不冒充完整日志检索系统 |
| 二进制或当前不支持类型 | 保留 item 身份和元数据，明确不参与数值分析 |

文本 / 日志原文需要该组范围的 **`evidence.read_sensitive`**。没有此权限时页面不请求原文；这属于权限限制，不表示未采集。当前历史界面单次最多返回 100 条，并说明截断、覆盖不足和原因。

**原文读取权与模型外发是两件事。** 通用数值及经过限制的名称、单位和语义标签可用于解释；自由说明保留在本地，不外发。文本 / 日志原文、任意 key 参数和不安全元数据不会直接进入外部模型。专用诊断扩展只在经过独立字段投影后提供受限结构化信息。

组卡片显示组成、最近观察与采集状态。组内一个 item 有新样本，不证明其余 items 都新鲜或健康；需逐项核对窗口与覆盖。

### 正确理解稀疏 history

官方模板可能使用“值未变化则丢弃”或“值未变化则按心跳保留”的预处理。**采集轮询周期、history 保留间隔和最近一次实际记录不是同一个概念。**

例如每分钟采集一次、每小时才保留不变值时，最近十分钟没有新 history，既可能是值未变，也可能存在资料缺口。应核对 `history_semantics`、轮询周期、心跳、实际样本时间和状态；不能补零、把旧值前向填充成当前测量，或仅凭空窗口判定采集失败。

同样，来源 API 能连通只证明来源可访问；对象已启用只说明调度开启，都不等于已经获得有效观察。

## 配置自动巡检

点击对象卡片“配置巡检”，在既有策略中选择该联合对象，指定负责人、范围、模式、分析周期、冷却和每日预算。

- **数据采集**：组默认 60 秒，可配置 30–3600 秒，负责读取已选项。
- **规则检查**：默认 300 秒，由确定性程序检查信号与覆盖。
- **综合巡检**：默认 1800 秒，按保存的模式与预算运行；异常紧急通道仍受冷却、队列和授权约束。

`rules_only` 不调用模型，结果是规则与覆盖说明。`live_redacted` 才调用真实模型，还需供应商配置、当前业务授权及明确外发许可。报告先解释现象、独立表层原因、联合候选、结论和建议，再按需展开事实、反证、未知、关系和图表。事实必须引用冻结证据；成功运行不表示所有解释都正确。人工变更建议必须要求人工批准，列出前提与复验，不授予执行权限。

一个组沿用原有 Instance 范围授权与巡检资源身份。单次调查最多五个资源、每位用户最多三个在途调查；组内 host 数不是该调查的数据库实例数。较大范围继续分组调度，不因建组绕过预算。后台运行不依赖浏览器一直打开；正常且无合格异常的周期保留历史，不为演示制造问题。

## 修改、暂停与历史报告

通过“编辑范围”调整名称、所选项、关系或采集周期。保存必须基于当前配置版本；冲突时重新读取后修改。已有来源绑定的地址与系统不能重指向，不同来源请另建来源与对象。

配置变更推进版本，使旧在途结果不能覆盖新范围。已经生成的报告继续使用原冻结清单、组成和时间窗，不会被新选择改写。暂停组停止新采集及相关巡检，保留已有历史；重新启用后核对新样本和策略状态。

从“问题分析”或巡检历史进入报告：先看模式、范围和覆盖，再读发生了什么、为什么、怎么做；需要核实时展开曲线、关系、引用与未知。旧报告缺完整摘要时保留旧版提示与原内容，不以规则补成新的 AI 输出。当前指标是新查询，不用来补写旧报告。大窗口使用有界序列表示，抽样、截断与个别序列无法保留都须说明；有限样本不能称为完整原始历史。上一轮正常周期为 18 条冻结曲线、17 条数值入模、1 条明确省略；受控锁周期为 18 条冻结、13 条数值入模、5 条明确省略，另有一条非空锁边。后者 11,576 字节未超过该次 12,000 字节硬界。这不表示所有冻结曲线均供模型读取或任意更大窗口均已验证。

关系仅表示登记、观察或候选解释。同一窗口变化、人工依赖线和模型措辞都不足以证明因果。实际变更由人员在外部执行，之后用新的有效样本复验；平台和模型没有任意 SQL、Shell 或自动修复入口。

### 读锁报告时不要只核对引用

上一轮 `46fd02bd…` 报告的锁链与冻结证据匹配，但第 4 条 CPU 事实把首值 3.358 写作范围下界约 3.4；实际最小值 2.7538、最大值 4.53549。引用可追溯不代表解释正确，阅读时还要区分端点、极值和统计范围。原输出保留，提示已补充该区别，仍不能保证避免误读。报告的 1 条 finding 仍待核验，不代表用户已签署确认或平台已经修复。

## 本轮与历史验证边界

本轮实际结果见[结论优先验收](acceptance-conclusion-first.md)，结构与引用检查不等于真实模型语义已验收。新请求输入硬界 24,000 字节、输出可配置到 3,000 tokens，仍服从更低显式预算及累计 token、调用、费用与工具限制；不保证全部曲线都入模。DeepSeek 等为私密可选配置，公开源码不硬编码个人 Pro 账号或密钥。

[上一轮验收](acceptance-analysis-groups.md)保留官方连续采样、范围选择、权限与冻结、正常及受控锁报告的限定结果，包括 CPU 区间误读和早期失败。上述 12KB 请求与冻结记录保持原样，不用新上限追认旧报告完整覆盖。[2026-11-08 验收](acceptance-zabbix.md)另保留旧版整组曲线被预算省略等缺口。

缺真实 counter reset epoch 时不把 SQL 累计摘要当作窗口差分。项目是个人隔离 Lab、真实监控观测和合成业务负载，不声称生产采用、自动修复或通用准确率；生产容量、长期稳定性与高可用未验证。[README](../README.md)展示当前主路径，旧界面保留在历史材料。
